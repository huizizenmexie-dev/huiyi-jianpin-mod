更新网站与使用部署包

推荐流程：继续使用 GitHub Desktop

  1. 打开正确仓库。确认 Local path 是桌面的 huiyi-jianpin-mod，查看 Changes 中本次修改。当前工作分支为 codex/lecprima-visual-refresh。
  2. 提交本地修改。填写 Summary，例如“统一产品图片并优化加载”，点击 Commit to 当前分支。
  3. 推送到 GitHub。点击 Push origin；若是新建的远程分支，按钮可能显示 Publish branch。
  4. 审阅后合并到 main。可在 GitHub 创建 Pull Request，检查修改后合并。当前配置仅在 main 收到推送时自动发布，也支持手动运行工作流。
  5. 确认发布成功。打开仓库 Actions，查看 Deploy GitHub Pages 是否成功；然后访问正式网址，用无痕窗口检查图片和语言切换。
提交到分支 ≠ 已更新正式网站。本次交付修改本地文件并提供部署包；正式站点何时更新，由您后续的提交、合并和 Pages 工作流结果决定。

部署 ZIP 的使用方法

  1. 将桌面的 ZIP 解压到一个新文件夹。打开后应直接看到 index.html、en/、zh-CN/、assets/、images/ 和 fonts/ 等内容。
  2. 在支持静态站点的主机上，把这些文件和文件夹整体上传到网站根目录。不要把多余的一层解压文件夹当成网站根目录。
  3. 当前部署包按域名根路径 / 和正式域名 https://lecprima.com 构建。若更换域名或部署到 /项目名/ 子目录，应使用源码修改构建环境并重新打包。

使用现有 GitHub Pages 工作流时，无需把 ZIP 放进仓库或上传到 GitHub Desktop；工作流会直接从源码构建。ZIP 适合作为静态成品备份，或交给其他托管服务。

在电脑上预览源码

在项目文件夹打开 PowerShell；准备好 Node.js（工作流使用 22）和 pnpm 后执行：

pnpm install --frozen-lockfile
pnpm run build
pnpm run start

浏览器打开 http://localhost:4173/en/。开发时可使用 pnpm run dev 并打开终端显示的地址。直接双击部署包里的 index.html 无法等同于真实网站服务。

图片替换规范

10 款产品的默认网页图片统一为 1200 × 1200，使用透明背景，并由白色图片框统一显示；另有 400、800 像素版本。场景图采用 3:2 比例，提供 480、960、1536 像素版本。

页面自动选择 AVIF，兼容回退使用 WebP。替换图片时须同步生成同名的各尺寸文件，不能只覆盖一张默认 WebP。维护人员可参照 scripts/optimize-media.mjs 与 docs/design/media-manifest.json；不要把整张高清 PNG 直接作为网页加载图。

原稿与网页文件分开保存。透明底 PNG 用于长期维护，各尺寸的 AVIF / WebP 用于网页加载。每次更换原稿后，请同步生成并提交所有网页尺寸，再进行构建验证。

收件验收与常见问题

更换收件邮箱与验收

  1. 用新的收件邮箱在 Web3Forms 获取对应 access key，按服务商提示验证；将代码中的 WEB3FORMS_ACCESS_KEY 替换，再构建发布。
  2. 如需同步变更公开邮箱，更新 client/src/content/site.ts 中的 CONTACT.email，并搜索旧邮箱，同步检查 client/src/pages/Contact.tsx 和 client/src/components/ErrorBoundary.tsx 的显示文字或链接。只改公开邮箱，不会自动改变表单转发邮箱。
  3. 发布后由您填写一次带“网站测试”备注的完整询盘，核对产品、联系信息和来源字段；检查收件箱和垃圾邮件箱，并验证回复是否指向测试者邮箱。

本次开发没有向真实邮箱提交询盘。Access key 是可出现在前端的表单标识，不是邮箱密码；仍应使用 Web3Forms 提供的反垃圾措施，并保留网站现有 honeypot 字段。

现象检查方法
修改后线上没变化先看分支是否已合并到 main、Actions 是否发布成功；再用无痕窗口或强制刷新排除旧缓存。

表单成功但没收到确认 Web3Forms 密钥绑定的邮箱、垃圾邮件目录及服务商状态；按第 3 页进行一次真实收件核对。
旧证书链接打不开部分历史证书链接仍由外部地址提供。应使用经核准的本地文件替换，并更新相关链接和证据记录。

发布前检查：pnpm run check、pnpm run test、pnpm run build、pnpm run validate-seo、pnpm run verify-static。随后检查手机和电脑上的首页、产品图、语言切换与询盘入口。

请保留 Git 历史、原始图片和每次桌面部署包。需要恢复旧版时，从 Git 历史恢复源码并重新发布；部署包只能恢复当时的静态成品。涉及认证、产能、产品功效等内容，应先核准资料再更新文案。
